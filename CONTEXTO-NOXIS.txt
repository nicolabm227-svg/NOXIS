1. QUÉ ES NOXIS
--------------------------------------------------------------------------------
NOXIS es un CATÁLOGO DE JUEGOS para PC, estático (HTML + CSS + JavaScript puro,
sin build, sin framework, sin base de datos). Muestra los juegos en una Home con
carriles ("Destacados" —ordenado por popularidad— y "Nuevos"), una vista "Explorar" con
filtros y búsqueda, y una "ventana de juego" tipo overlay con descripción,
requisitos, galería, DLC y enlaces de descarga/compra.

- Todo el contenido sale de un único archivo de datos: js/data.js (objeto
  global NOXIS.Data). No hay backend de contenido; solo hay un Worker de
  Cloudflare para analítica/ranking de popularidad (opcional, con fallback).
- El sitio se publica en Cloudflare (Workers), conectado por git: al hacer push
  a la rama main, Cloudflare redespliega automáticamente (~1-2 min).
- DERECHOS: el sitio, su código, diseño y ESTRUCTURA están reservados (LICENSE,
  "todos los derechos reservados"). El footer muestra el copyright y un aviso de
  terceros. Los JUEGOS (nombres/imágenes/marcas) NO son nuestros: pertenecen a
  sus titulares y se muestran solo a modo informativo.

2. STACK Y ESTRUCTURA DE ARCHIVOS
--------------------------------------------------------------------------------
- HTML: index.html (una sola página; contiene las vistas y los <script>/<link>).
- CSS (5): css/global.css (tokens/base + fondo de orbes), css/components.css
  (header/loader/tarjetas), css/home.css (Home + estilos del efecto de escritura),
  css/explore.css, css/game.css.
- JS (8, en este orden en index.html):
    1) analytics.js  -> NOXIS.Analytics  (eventos anónimos al Worker)
    2) data.js       -> NOXIS.Data       (fuente de datos + facets + búsqueda)
    3) app.js        -> NOXIS.App        (núcleo: loader, router, navegación, buscador)
    4) home.js       -> NOXIS.RouterHooks (render de la Home)
    5) explore.js    -> NOXIS.RouterHooks (filtros/orden/paginación de Explorar)
    6) game.js       -> NOXIS.Game       (ventana overlay del juego)
    7) orbs.js       (autónomo, SIN namespace: genera el fondo de orbes + parallax)
    8) typewriter.js -> NOXIS.Typewriter (efecto de escritura de encabezados)
- Worker del ranking: worker/index.js + worker/wrangler.toml (KV NOXIS_EVENTS).
- Assets: assets/images/ (logo, favicon, apple-touch-icon, portadas y galerías de
  juegos en assets/images/games/<id>/).
- Documentación: README.md, ARCHITECTURE.md, DESIGN_SYSTEM.md, DEVELOPMENT.md,
  DEPLOY.md, PROJECT_STATUS.md, AI_CONTEXT.md, CHANGELOG.md, AGREGAR-JUEGO.md,
  CONTRIBUTING.md y este CONTEXTO-NOXIS.txt.
- Material crudo (gitignored, NO se publica): "Contenedor de juegos/<Nombre>/"
  con Portada, Complementaria N, informacion.txt y .torrent.

3. ARQUITECTURA Y FUNCIONES (APIs PÚBLICAS)
--------------------------------------------------------------------------------
Patrón: cada módulo se registra en window.NOXIS. Las vistas leen datos SOLO a
través de NOXIS.Data (si algún día se cambia a Firebase, se sustituye el interior
sin tocar las vistas).

NOXIS.Data (js/data.js):
  - init()                 Carga popularidad desde el Worker (solo en producción;
                           en local se omite). Reordena con fallback estático.
  - getAllGames()          Array completo de juegos.
  - getSectionGames(key)   Juegos de una sección (featured|new).
  - getSections()          Carriles de la Home SIN repetir juegos; adapta el
                           tamaño por sección (máx. 8) y omite las vacías.
  - searchGames(query)     Búsqueda por título/categoría/género/subtítulo.
  - getFacets()            Facetas para filtros: categories, genres, os, years.
  - getTools()             Herramientas del bloque lateral (5).
  - filterGames({...})     Filtra/ordena por category, genre, os, year, sort.

NOXIS.App (js/app.js):
  - init()                 Arranca loader, router, navegación y buscador global.
  - openGame(id)           Abre la ventana de un juego por id.
  - navigate(route)        Cambia de vista ("home" | "explore").
  - NOXIS.RouterHooks      Lo definen home.js y explore.js para inicializar cada
                           vista cuando el router entra en ella.

NOXIS.Game (js/game.js):
  - open(id)               Renderiza y abre el overlay del juego.
  - close()                Cierra (también con Escape, backdrop o punto rojo).
  - render(game)           HTML del contenido (tabs, galería, requisitos, DLC...).

NOXIS.Analytics (js/analytics.js):
  - endpoint               URL del Worker.
  - track(type, data)      Envía evento anónimo (open/download/purchase) con
                           sendBeacon; inactivo en local (file:/localhost).

NOXIS.Typewriter (js/typewriter.js):
  - play(root)             Escribe letra a letra los encabezados de la vista
                           indicada (root = elemento de la vista). Scope-aware
                           (cada vista tiene sus propios grupos). Se omite con
                           prefers-reduced-motion.

orbs.js: autónomo. Genera 40 orbes e implementa el parallax de la capa. Sin API.

4. MODELO DE DATOS (SCHEMA DE UN JUEGO)
--------------------------------------------------------------------------------
Cada elemento del array `games` de js/data.js:

  {
    id, title, category, genre, os: ["Windows"], year,
    popular (0..100, fallback de orden), rating (★ X.X / 10),
    featured (bool -> aparece en "Destacados"),
    sub ("<género> · <año>", subtítulo de la tarjeta),
    cover ("assets/images/games/<id>/portada.jpg"),
    description,                          // párrafo de la descripción
    requirements: { min: {...}, rec: {...} },  // os, cpu, ram, gpu, vram, storage, ...(opcional)
    specs: { plataforma, idiomaTextos, idiomaVoces, anio, tamano, formato, genero },
    links: { download, purchase },        // abren en pestaña nueva
    gallery: [".../complementaria-1.jpg", ...],
    dlc: ["Nombre", ...]                  // OPCIONAL
  }

- specs.tamano alimenta el "chip de tamaño" de la tarjeta.
- Todo bloque es opcional: la ventana degrada con elegancia (botones deshabilitados,
  pestañas vacías, etc.). Si un juego no tiene DLC, se omite el campo `dlc`.
- Filtros de Explorar se construyen desde getFacets(): category, genre, os, year.
- Orden: `popular` (fallback) / `year` / `rating`.

5. SISTEMA DE DISEÑO (RESUMEN)
--------------------------------------------------------------------------------
Ver DESIGN_SYSTEM.md para el detalle. Claves:
- Estética oscura/tecnológica. Tokens: --bg #05060a, --accent #3b82f6,
  --accent-soft #6ea8ff, --violet-soft #a78bfa, --text #f5f7fc; --grad-hero.
- Tipografías: Sora + Inter (Google Fonts, display=swap).
- Componentes: header (logo assets/images/logo.webp), loader, tarjetas
  (.game-card con chip de tamaño), ventana de juego (.game-window), pills,
  acordeón de filtros, paginación, "volver arriba".

FONDO DE ORBES (js/orbs.js + css/global.css):
- 40 orbes IDÉNTICOS (mismo tamaño/color/glow; solo cambian posición y tempo),
  deliberadamente discretos. Tamaño 7x7px, opacidad 0.75, glow 10px/0.55,
  núcleo #d4e3ff. Ascienden lento con leve vaivén (orb-float).
- Deterministas (LCG semilla fija 20261016), fixed z-index:-1, pointer-events:none.
- Parallax sutil (±16px) solo en punteros finos y sin reduced-motion.
- Móvil: se ocultan los últimos 16 (quedan 24). reduced-motion: estáticos.

EFECTO DE ESCRITURA / TYPEWRITER (js/typewriter.js + css/home.css):
- Los encabezados de Inicio (eyebrow/título/subtítulo) y de Explorar se escriben
  letra a letra con cadencia orgánica y micro-pausas tras comas/puntos; cursor
  fino (1.5px, degradado + glow) que parpadea y se desvanece al terminar.
- SIN destello: las letras se envuelven y ocultan apenas carga el módulo (nunca
  se ve el texto completo antes de animar). En la primera carga, arranca
  sincronizado con el fundido del loader; en Explorar, al entrar a la vista.
- El título de Inicio conserva el degradado (--grad-hero) repartido por letra
  (medido tras document.fonts.ready). Texto animado aria-hidden + aria-label.
- Scope-aware: play(root). Se re-ejecuta al volver a cada vista. reduced-motion:
  texto plano sin spans.

6. CÓMO AGREGAR UN JUEGO (RESUMEN)
--------------------------------------------------------------------------------
Detalle completo en AGREGAR-JUEGO.md. Pasos:
  1) Elegir id (minúsculas, guiones).
  2) Copiar/renombrar assets a assets/images/games/<id>/:
     Portada.* -> portada.jpg ; Complementaria N.* / imagen N.* -> complementaria-N.<ext>.
     OJO: la extensión debe coincidir con el contenido real (mirar magic bytes).
  3) Agregar el objeto del juego a `games` en js/data.js (ver schema §4).
  4) Volcar DLC en `dlc` si la ficha los menciona (no inventar).
  5) node --check js/data.js.
  6) Subir ?v=N en index.html (cache-busting).
  7) Probar en Home, Explorar y ficha (incl. bloque DLC). Verificar 0 errores/404.
  8) git add ... && git commit && git push origin main (Cloudflare publica solo).

12. DECISIONES Y NOTAS DE CONVERSACIÓN
--------------------------------------------------------------------------------
- Regla de oro: las vistas NO se tocan al agregar juegos; todo se genera desde
  NOXIS.Data.
- Orbes: se probaron varias iteraciones hasta quedar "uniformes y discretos"
  (40 idénticos, 7px). Se evitó `filter: blur` y variantes de tamaño.
- Typewriter: se corrigió el destello inicial ocultando las letras al cargar el
  módulo y sincronizando el arranque con el loader. Luego se generalizó a
  Explorar (scope-aware) en vez de duplicar código.
- Home: se eliminó la sección "Más populares" por ser redundante con "Destacados"
  (todos los juegos son `featured` y el dedupe dejaba ese carril con 1 tarjeta).
  "Destacados" ahora se ordena por POPULARIDAD (descargas/interacciones del Worker,
  con fallback al `popular` estático) y se quitó el `slice(0, 8)` de los `select`
  para que `getSections()` reparta los 11 juegos (6 + 5). El buscador sigue
  reordenando "Destacados".
- Derechos: se reservan los derechos del sitio/estructura (LICENSE) y se avisa en
  el footer. Decisión clave: NO reclamar propiedad sobre los juegos; el LICENSE
  deja explícita la excepción de contenido de terceros.
- Nombres de imágenes del contenedor varían (Portada/PORTADA, "imagen 1",
  "complementaria1", "complementarai4" (typo), "imagen1 .webp" con espacio):
  se normalizan SIEMPRE al copiar.
- El informacion.txt de Gears of War: E-Day traía el enlace de Descargar
  EQUIVOCADO (apuntaba al torrent de The Witcher 3). Corregido con el enlace
  real provisto por el usuario.
- Datos no presentes en las fichas (decisiones provisionales, ver §13): ratings,
  año de Witcher 3 (2026 según su ficha), requisitos ausentes en GTA V, sufijos
  de edición en los títulos.
